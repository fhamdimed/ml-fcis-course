Project Overview

In this group project, you will design, implement, and evaluate a small Integrated Machine Learning Decision System.

Each group will consist of 3 students.

The project is submitted in Week 15 and is worth 10 marks.

The project focuses on four course learning outcomes:

  • CLO2: Analyze datasets and apply appropriate preprocessing, transformation, and feature engineering techniques.
  • CLO3: Construct and analyze machine learning models by applying algorithmic principles and internal computations.
  • CLO4: Apply supervised and unsupervised learning techniques to solve practical problems and interpret their outcomes.
  • CLO5: Evaluate machine learning models using appropriate metrics and justify decisions based on performance trade-offs and real-world context.

Your project must follow the complete Machine Learning workflow:

\[ \boxed{ \text{Real problem} \rightarrow \text{Data} \rightarrow \text{Preprocessing} \rightarrow \text{Model(s)} \rightarrow \text{Training} \rightarrow \text{Evaluation} \rightarrow \text{Interpretation} } \]

The objective is not simply to obtain the highest possible model score.

You are expected to demonstrate that you understand:

  • what problem the model is solving;
  • what one observation represents;
  • why each feature is appropriate;
  • how data quality affects learning;
  • why preprocessing choices are needed;
  • how the selected models learn or make predictions;
  • how model complexity affects generalization;
  • which evaluation metrics are appropriate;
  • how validation evidence should guide model selection;
  • what the final results mean in the application context.
ImportantCore assessment principle

A working notebook is only part of the project.

Marks are awarded mainly for correct Machine Learning reasoning, reproducible methodology, experimental analysis, interpretation, and demonstrated individual understanding.

Your group will choose a real-world data problem and build a Machine Learning system that supports a meaningful prediction or decision.

Possible domains include:

  • education;

Your project must contain:

  2. a comparison of at least two appropriate supervised models or model configurations;
  3. a clear validation and final-test strategy;

  5. interpretation of results in the original problem context.

A small, well-designed project is better than a very large system with weak analysis.

Your problem should be complex enough to require meaningful data preparation and model evaluation, but small enough for all group members to understand completely.

Part I — Problem and Dataset

Goal

Choose a dataset and define a clear Machine Learning problem.

Your report/notebook must explicitly state:

  • the real-world problem;
  • the prediction or decision being supported;
  • the unit of observation;
  • the target variable \(y\);
  • the input features \(X\);
  • whether the supervised task is classification or regression;
  • what information is available at prediction time;
  • who could use the model output and for what purpose.

Dataset Requirements

Your dataset should normally contain at least:

  • 300 observations;
  • 5 meaningful input features;
  • one clearly defined supervised target;
  • at least one realistic preprocessing or data-quality issue;
  • enough variation to make model comparison meaningful.

A smaller dataset may be used only with instructor approval and a clear justification.

The dataset may come from:

  • a public open-data source;
  • a recognized educational dataset repository;
  • an instructor-approved source;
  • data generated or collected by your group when ethically and legally appropriate.

Data Source Documentation

You must identify:

  • dataset name;
  • source;
  • number of rows and columns used;
  • meaning of the target;
  • meaning and type of the main features;
  • any important limitations of the data.

Do not include direct personal identifiers such as names, student IDs, account numbers, or similar identifiers as predictive features.

Problem Formulation Evidence

Your notebook/report must answer:

  1. What exactly should the model predict?
  2. At what point would the prediction be made?
  3. Which features are legitimate at that point?
  4. Which variables could create target or future-information leakage?
  5. What simple baseline should the learned models beat?

Part II — Data Understanding and Preprocessing

Goal — CLO2

Analyze the dataset and create a justified preprocessing workflow.

Your analysis must include appropriate evidence such as:

  • data types;
  • missing values;
  • duplicate records;
  • invalid or inconsistent values;
  • class balance for classification;
  • descriptive statistics;
  • distributions;
  • outliers;
  • categorical levels;
  • correlations or relevant associations;
  • feature ranges and scale differences.

Required Preprocessing

Apply only the preprocessing steps that your data actually require.

Possible steps include:

  • missing-value imputation;
  • duplicate handling;
  • invalid-value correction;
  • categorical encoding;
  • standardization or normalization;
  • transformations for strongly skewed variables;
  • outlier investigation;
  • feature engineering;
  • removal of identifiers or leakage variables.

For every major preprocessing step, explain:

Why is this step appropriate for this dataset and these models?

Train-Only Fitting Rule

If a transformation learns information from the data, such as:

  • mean or median imputation;
  • scaling;
  • category encoding;
  • PCA;

it must be fitted using the appropriate training data only when it is part of the supervised predictive workflow.

Use a reproducible pipeline where appropriate.

WarningLeakage is a project-level error

Do not fit preprocessing on the full dataset and then report test performance as if the test set had remained unseen.

A pipeline that leaks information into validation or test data can produce misleading results even when the code runs correctly.

Required Preprocessing Experiment

Investigate at least one representation or preprocessing choice.

Examples:

  • scaled vs. unscaled KNN;
  • original vs. engineered features;
  • with vs. without a suspicious outlier-handling rule;
  • alternative encoding choices;
  • linear vs. polynomial representation;
  • with vs. without regularization.

Predict the expected effect before running the experiment, then interpret the observed result.

Part III — Supervised Model Construction

Goal — CLO3 and CLO4

Train and compare at least two appropriate supervised models or model configurations from the course.

Classification Projects

Possible model families include:

  • Logistic Regression;
  • Decision Tree;
  • K-Nearest Neighbors;
  • Neural Network.

Regression Projects

Possible model/configuration comparisons include:

  • simple vs. multiple Linear Regression;
  • linear vs. polynomial regression;
  • unregularized vs. Ridge regression;
  • unregularized vs. Lasso regression;
  • alternative polynomial degrees or regularization strengths.

The two models must not be arbitrary.

Explain why each model is appropriate for your problem and data.

Baseline

Before comparing learned models, create a simple baseline.

Examples:

Classification

  • majority-class classifier;
  • simple rule-based baseline when justified.

Regression

  • training-target mean;
  • training-target median.

Explain what it would mean if your learned models cannot beat the baseline.

Required Algorithmic Evidence — CLO3

For one selected model, include a small transparent calculation or trace showing its internal logic.

Choose an appropriate example such as:

  • one Linear Regression prediction from learned coefficients;
  • one gradient-descent update;
  • one Logistic Regression forward/loss/update calculation;
  • one Decision Tree entropy/information-gain split;
  • one KNN distance and majority-vote calculation;
  • one Neural Network forward/backpropagation step.

The purpose is to connect your code to the algorithmic principles studied in the course.

ImportantLibrary use does not replace understanding

You may use scikit-learn for the project models.

However, every group member should be able to explain what the selected model is doing internally and what its important hyperparameters control.

Required Model Experiment

Investigate at least one model-complexity or hyperparameter choice.

Examples include:

  • polynomial degree;
  • regularization strength;
  • Logistic Regression threshold;
  • Decision Tree depth or pruning parameter;
  • KNN value of \(k\);
  • Neural Network hidden-layer size.

Use validation evidence to explain underfitting, overfitting, or performance trade-offs.

Part IV — Evaluation and Model Selection

Goal — CLO5

Evaluate the supervised models using metrics appropriate to the task.

Classification Projects

Use a suitable subset of:

  • confusion matrix;
  • accuracy;
  • precision;
  • recall;
  • specificity;
  • \(F_1\) score;
  • ROC-AUC or Precision-Recall analysis when appropriate;
  • application-specific cost or threshold analysis.

If the dataset is imbalanced, do not rely on accuracy alone.

Regression Projects

Use suitable metrics such as:

  • MAE;
  • MSE;
  • RMSE;
  • \(R^2\);
  • residual analysis.

Required Validation Discipline

Your project must clearly distinguish:

  • training data — used to fit model parameters;
  • validation data / cross-validation — used to compare models and tune hyperparameters;
  • final test data — used once for the final unbiased evaluation.

You must not choose the final model based on test-set performance.

Required Comparative Evidence

Compare at least two candidate models/configurations in a table.

A useful table may include:

Model A
Model B

Your analysis must explain:

  • why one model performs better or worse;
  • whether the difference is practically meaningful;
  • whether a simpler model is preferable when performance is similar;
  • what error type matters most in the application;
  • why your final model was selected.

Error Analysis

Include at least one analysis of model errors.

Examples:

Classification

  • examples of false positives;
  • examples of false negatives;
  • threshold trade-offs;
  • subgroup or feature-pattern analysis when appropriate.

Regression

  • largest residuals;
  • systematic residual pattern;
  • performance for different ranges of the target.

Do not simply list errors. Explain what they reveal about the model or data.

Part V — Unsupervised Analysis

Goal — CLO4

Add one unsupervised analysis component using either:

  1. K-Means Clustering, or
  2. Principal Component Analysis (PCA).

This component should provide a useful perspective on the same dataset or a meaningful subset of its numerical features.

Option A — K-Means

If you use K-Means:

  • select meaningful numerical features;
  • justify scaling;
  • compare more than one value of \(K\);
  • use inertia and/or silhouette evidence;
  • interpret cluster centroids or profiles in original units;
  • explain why cluster IDs themselves have no semantic meaning.

Option B — PCA

If you use PCA:

  • justify scaling;
  • report explained variance ratios;
  • show cumulative explained variance;
  • choose and justify the number of retained components;
  • interpret important loadings;
  • use a 2D projection when useful;
  • explain what information is lost when dimensions are removed.

Connection to the Supervised Problem

Explain what the unsupervised analysis adds.

Examples:

  • reveals natural customer groups;
  • shows whether observations form visible structure;
  • reduces redundant correlated features;
  • helps visualize high-dimensional data;
  • suggests outliers or unusual cases;
  • provides a compact representation for further analysis.
NoteUnsupervised structure is not ground truth

Do not automatically treat a cluster as a real category or a principal component as a causal factor.

Interpret discovered structure carefully and support your claims with the feature patterns in the data.

Part X — What Strong Projects Demonstrate

A strong project does more than run successfully.

It demonstrates that students can:

  • define a meaningful prediction problem;
  • understand the structure and limitations of a dataset;
  • identify leakage and invalid features;
  • apply justified preprocessing;
  • create a reproducible pipeline;
  • establish a baseline;
  • construct appropriate supervised models;
  • connect library code to algorithmic principles;
  • compare model complexity using validation evidence;
  • choose metrics that match the task;
  • analyze important errors;
  • keep the final test set separate from model selection;
  • apply K-Means or PCA meaningfully;
  • interpret results in the original application context;
  • explain limitations rather than overstate conclusions;
  • predict the effect of a small change before running code.

Part XI — Common Mistakes to Avoid

Avoid the following:

  • choosing a dataset before defining a clear question;
  • using direct identifiers as predictive features without justification;
  • keeping future-information or target-leakage variables;
  • preprocessing the full dataset before final evaluation;
  • comparing models only by training performance;
  • reporting only one metric for an imbalanced classification problem;
  • trying many models without explaining why they were chosen;
  • using the test set to tune hyperparameters;
  • reporting tables without interpretation;
  • claiming that a higher score automatically means a better real-world decision;
  • applying K-Means to unscaled features with very different units without justification;
  • assigning semantic cluster names without inspecting their profiles;
  • interpreting PCA loadings causally;
  • copying a complete workflow that group members cannot explain;
  • dividing the project so strictly that each student understands only one section.
